# WeKWS 替换方案详细说明

## 一、当前 ESP32 项目技术栈

```
┌─────────────────────────────────────────────────────┐
│                    音频输入 (麦克风)                  │
└─────────────────────┬───────────────────────────────┘
                      ▼
┌─────────────────────────────────────────────────────┐
│   ESP-SR AFE (音频前端)                              │
│   - AEC (回声消除)                                   │
│   - NS (噪声抑制)                                    │
│   - BF (波束成形，多麦克风)                           │
└─────────────────────┬───────────────────────────────┘
                      ▼
┌─────────────────────────────────────────────────────┐
│   ESP-SR Wakenet/Multinet (乐鑫闭源模型)             │
│   - 预训练唤醒词: "Hi 乐鑫", "小智同学" 等            │
│   - Multinet: 自定义命令词                           │
│   - 模型格式: 乐鑫专有格式 (.bin)                    │
└─────────────────────┬───────────────────────────────┘
                      ▼
┌─────────────────────────────────────────────────────┐
│   wake_word_sdk 封装层                               │
│   - WakeWord 抽象接口                                │
│   - EspWakeWord, AfeWakeWord, CustomWakeWord        │
└─────────────────────────────────────────────────────┘
```

**问题**: 乐鑫的 Wakenet/Multinet 模型是闭源的，无法：
1. 训练自己的唤醒词模型
2. 修改模型架构
3. 完全控制模型行为

---

## 二、WeKWS 技术栈

```
┌─────────────────────────────────────────────────────┐
│   WeKWS 训练框架 (Python/PyTorch)                    │
│   - 开源训练代码                                     │
│   - 可训练任意唤醒词                                 │
│   - 支持多种模型架构 (TCN/MDTC/FSMN/GRU)             │
└─────────────────────┬───────────────────────────────┘
                      ▼
┌─────────────────────────────────────────────────────┐
│   ONNX 模型导出                                      │
│   - 标准化的模型格式                                 │
│   - 可部署到多种平台                                 │
└─────────────────────┬───────────────────────────────┘
                      ▼
┌─────────────────────────────────────────────────────┐
│   C++ 运行时 (runtime/core)                          │
│   - ONNX Runtime 推理                                │
│   - 80维 Fbank 特征提取                              │
│   - 支持: x86, Android, RaspberryPi                  │
│   - ❌ 不支持: ESP32                                 │
└─────────────────────────────────────────────────────┘
```

---

## 三、方案 A: 完全替换 (全部使用 WeKWS)

### 技术路线
```
┌─────────────────────────────────────────────────────┐
│                    音频输入                          │
└─────────────────────┬───────────────────────────────┘
                      ▼
┌─────────────────────────────────────────────────────┐
│   ❌ 移除 ESP-SR AFE                                 │
│   (或自己实现简单的预处理)                           │
└─────────────────────┬───────────────────────────────┘
                      ▼
┌─────────────────────────────────────────────────────┐
│   移植 WeKWS 特征提取 (C++)                          │
│   - 80维 Fbank 特征                                  │
│   - FFT + Mel 滤波器组                               │
└─────────────────────┬───────────────────────────────┘
                      ▼
┌─────────────────────────────────────────────────────┐
│   移植 ONNX Runtime Micro 到 ESP32                   │
│   - 需要大量移植工作                                 │
│   - 或使用 onnxruntime-esp32 社区项目                │
└─────────────────────┬───────────────────────────────┘
                      ▼
┌─────────────────────────────────────────────────────┐
│   WeKWS ONNX 模型推理                                │
│   - 自己训练的唤醒词模型                             │
│   - MDTC_Small (31K参数) 推荐                        │
└─────────────────────────────────────────────────────┘
```

### 使用的技术

| 组件 | 技术 | 来源 |
|------|------|------|
| 特征提取 | Fbank 80维 | 移植 WeKWS C++ 代码 |
| 模型推理 | ONNX Runtime Micro | 需要移植到 ESP32 |
| 模型训练 | PyTorch + WeKWS | WeKWS 开源框架 |
| 模型格式 | ONNX | WeKWS 导出 |

### 优点
- 完全开源，完全可控
- 可以训练任意唤醒词

### 缺点
- **工作量巨大**: ONNX Runtime 移植到 ESP32 非常复杂
- **失去 AFE**: 没有回声消除和噪声抑制
- **风险高**: 可能遇到各种兼容性问题

## 四、方案 B: 混合方案 (保留 AFE + 使用 TFLite)

### 技术路线
```
┌─────────────────────────────────────────────────────┐
│                    音频输入                          │
└─────────────────────┬───────────────────────────────┘
                      ▼
┌─────────────────────────────────────────────────────┐
│   ✅ 保留 ESP-SR AFE (音频前端)                      │
│   - AEC (回声消除) - 保留                            │
│   - NS (噪声抑制) - 保留                             │
│   - 输出干净的音频                                   │
└─────────────────────┬───────────────────────────────┘
                      ▼
┌─────────────────────────────────────────────────────┐
│   移植 WeKWS 特征提取 (C++)                          │
│   - 80维 Fbank 特征                                  │
│   - 或使用 ESP-SR 的 Fbank (如果兼容)                │
└─────────────────────┬───────────────────────────────┘
                      ▼
┌─────────────────────────────────────────────────────┐
│   TensorFlow Lite Micro (ESP32 官方支持)             │
│   - 乐鑫官方支持，稳定                               │
│   - 已有成熟的 ESP32 移植                            │
└─────────────────────┬───────────────────────────────┘
                      ▼
┌─────────────────────────────────────────────────────┐
│   WeKWS 模型 (转换为 TFLite 格式)                    │
│   PyTorch → ONNX → TFLite                           │
│   - 量化为 INT8 减少内存                             │
└─────────────────────────────────────────────────────┘
```

### 使用的技术

| 组件 | 技术 | 来源 |
|------|------|------|
| 音频前端 | ESP-SR AFE | 乐鑫官方 (保留) |
| 特征提取 | Fbank 80维 | 移植 WeKWS 或复用 ESP-SR |
| 模型推理 | TensorFlow Lite Micro | 乐鑫官方支持 |
| 模型训练 | PyTorch + WeKWS | WeKWS 开源框架 |
| 模型格式 | TFLite (INT8 量化) | ONNX → TFLite 转换 |

### 模型转换流程
```
WeKWS PyTorch 模型
       │
       ▼ (export_onnx.py)
    ONNX 模型
       │
       ▼ (onnx2tf 或 tf2onnx)
  TensorFlow SavedModel
       │
       ▼ (TFLite Converter + 量化)
   TFLite INT8 模型
       │
       ▼
  ESP32 TFLite Micro 推理
```

### 优点
- **保留 AFE**: 继续享受回声消除和噪声抑制
- **TFLite 成熟**: 乐鑫官方支持，稳定可靠
- **可控风险**: 分步实施，风险可控

### 缺点
- 模型转换可能有精度损失
- 需要验证 TFLite 转换后的模型效果

## 五、方案 C: 仅训练替换 (最保守)

### 技术路线
```
┌─────────────────────────────────────────────────────┐
│   使用 WeKWS 训练自定义唤醒词                        │
│   - 准备训练数据                                     │
│   - 训练 MDTC/FSMN 模型                              │
└─────────────────────┬───────────────────────────────┘
                      ▼
┌─────────────────────────────────────────────────────┐
│   尝试转换为 ESP-SR 格式                             │
│   - 研究 ESP-SR 模型格式                             │
│   - 可能需要逆向工程                                 │
│   - ⚠️ 可能不可行                                   │
└─────────────────────┬───────────────────────────────┘
                      ▼
┌─────────────────────────────────────────────────────┐
│   ✅ 继续使用 ESP-SR 推理框架                        │
│   - 不修改现有代码                                   │
│   - 只替换模型文件                                   │
└─────────────────────────────────────────────────────┘
```

### 使用的技术

| 组件 | 技术 | 来源 |
|------|------|------|
| 全部 | ESP-SR | 乐鑫官方 (保留) |
| 模型训练 | WeKWS | 仅用于训练 |
| 模型格式 | ESP-SR 专有格式 | 需要转换 (可能不可行) |

### 优点
- 不修改现有代码
- 风险最低

### 缺点
- **可能不可行**: ESP-SR 模型格式是闭源的
- 需要逆向工程 ESP-SR 模型格式
- 乐鑫没有公开模型格式规范

## 七、推荐方案: 方案 B (混合方案)

**理由**:
1. TFLite Micro 在 ESP32 上有乐鑫官方支持
2. 保留 AFE 的音频处理能力
3. WeKWS 的训练流程成熟，模型效果好
4. 工作量适中，风险可控

### 具体实施步骤

#### Phase 1: 环境准备 (1周)
- 搭建 WeKWS 训练环境
- 准备训练数据 (正样本 + 负样本)
- 选择模型架构 (推荐 MDTC_Small)

#### Phase 2: 模型训练 (1-2周)
- 使用 Max-Pooling Loss 训练
- 导出 ONNX 模型
- 转换为 TFLite 格式并量化 (INT8)

#### Phase 3: ESP32 集成 (2-3周)
- 移植 WeKWS 特征提取代码
- 集成 TFLite Micro 推理
- 实现 WekwsWakeWord 类

#### Phase 4: 测试优化 (1周)
- 功耗测试
- 准确率测试
- 延迟优化

## 八、WeKWS 项目详细信息

### 项目地址
https://github.com/wenet-e2e/wekws

### 支持的模型架构

| 模型 | 参数量 | 特点 |
|------|--------|------|
| GRU | 203K | 循环神经网络 |
| TCN | 134K | 时序卷积网络 |
| DS_TCN | 287K | 深度可分离卷积 |
| MDTC | 31K-156K | 多尺度时序卷积 (推荐) |
| FSMN | 756K | 前馈序列记忆网络 |

### 特征提取参数
- 采样率: 16kHz
- Fbank 维度: 80 维
- 帧长: 25ms
- 帧移: 10ms

### 支持的数据集
- Hey Snips
- Google Speech Command
- Hi Miya (嗨米雅)
- Hi Xiaowen (嗨小问)
