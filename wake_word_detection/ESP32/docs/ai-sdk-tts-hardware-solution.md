# ai-sdk 内置硬件驱动 - TTS 功能详细技术方案

## 一、整体架构

```
+------------------------------------------+
|              ai-sdk                      |
+------------------------------------------+
|                                          |
|  +----------------+  +----------------+  |
|  |  TTS Client    |  |  ASR Client    |  |
|  +----------------+  +----------------+  |
|           |                              |
|           v                              |
|  +----------------+                      |
|  |  Audio Core    |                      |
|  |  - Opus解码    |                      |
|  |  - 重采样       |                      |
|  |  - 播放队列    |                      |
|  +----------------+                      |
|           |                              |
|           v                              |
|  +----------------+                      |
|  | Audio HAL      |  <- 硬件抽象层       |
|  +----------------+                      |
|           |                              |
|           v                              |
|  +------+------+------+------+------+   |
|  |ES8311|ES8388|ES8374|NoCode|PDM   |   |
|  +------+------+------+------+------+   |
|                驱动层                   |
+------------------------------------------+
           |
           v
+------------------------------------------+
|           硬件 (厂商的板子)             |
+------------------------------------------+
```

## 二、分层说明

### 第 1 层：TTS Client

**职责**：与服务器通信，接收 TTS 数据

| 功能 | 说明 |
|------|------|
| 连接服务器 | WebSocket/HTTP |
| 接收数据 | 收 Opus 编码的音频包 |
| 转发数据 | 发到 Audio Core |

### 第 2 层：Audio Core

**职责**：音频处理和播放调度

| 功能 | 说明 |
|------|------|
| Opus 解码 | 用 esp_opus_dec 解码成 PCM |
| 重采样 | 用 esp_ae_rate_cvt 转换采样率 |
| 播放队列 | 缓冲 PCM 数据，异步播放 |
| 状态管理 | 播放中/暂停/停止 |

### 第 3 层：Audio HAL

**职责**：硬件抽象，统一接口

| 接口 | 说明 |
|------|------|
| Init | 初始化硬件 |
| OutputData | 播放 PCM 数据 |
| SetVolume | 设置音量 |
| Enable | 开关输出 |
| GetSampleRate | 获取采样率 |

### 第 4 层：驱动层

**职责**：具体硬件操作

| 驱动 | 依赖 |
|------|------|
| ES8311 | esp_codec_dev + I2S |
| ES8388 | esp_codec_dev + I2S |
| NoCodec | I2S 直连 |
| PDM | I2S PDM 模式 |

## 三、配置系统设计

### 配置项分类

| 类别 | 配置项 |
|------|--------|
| 芯片类型 | 选择哪种音频芯片 |
| I2S 配置 | MCLK/BCLK/WS/DOUT/DIN 引脚 |
| I2C 配置 | SDA/SCL 引脚、端口号、地址 |
| 功放配置 | PA 控制引脚、电平反转 |
| 采样率 | 输入/输出采样率 |
| 通道数 | 单声道/双声道 |

### 配置方式选择

| 方式 | 优点 | 缺点 |
|------|------|------|
| Kconfig | ESP-IDF 标准，有 GUI | 配置项多时复杂 |
| 结构体 | 简单直接 | 需编译 |
| JSON | 运行时可改 | 占内存 |

## 四、支持的硬件列表

### 类型 A：用 esp_codec_dev 的芯片

| 芯片 | I2C | I2S | 特点 |
|------|-----|-----|------|
| ES8311 | 需要 | 需要 | 单编解码器，最常用 |
| ES8388 | 需要 | 需要 | 双编解码器 |
| ES8374 | 需要 | 需要 | 双编解码器 |
| ES8389 | 需要 | 需要 | 双编解码器 |
| AW88298 | 需要 | 需要 | 智能功放 |

### 类型 B：不用 esp_codec_dev

| 方案 | I2C | I2S | 特点 |
|------|-----|-----|------|
| I2S 双工 | 不需要 | 需要 | 同组引脚输入输出 |
| I2S 单工 | 不需要 | 需要 | 分开的输入输出 |
| PDM | 不需要 | PDM | 数字麦克风 |

## 五、厂商接入流程

```
1. 厂商查看支持的芯片列表
   ↓
2. 选择自己用的芯片
   ↓
3. 填写配置（引脚、采样率等）
   ↓
4. 编译、烧录、完成
```

### 厂商需要提供的信息

| 信息 | 示例 |
|------|------|
| 芯片类型 | ES8311 |
| I2S MCLK | GPIO_NUM_0 |
| I2S BCLK | GPIO_NUM_45 |
| I2S WS | GPIO_NUM_46 |
| I2S DOUT | GPIO_NUM_47 |
| I2S DIN | GPIO_NUM_48 |
| I2C SDA | GPIO_NUM_1 |
| I2C SCL | GPIO_NUM_2 |
| I2C 端口 | I2C_NUM_0 |
| I2C 地址 | 0x18 |
| PA 引脚 | GPIO_NUM_38 |
| 输出采样率 | 16000 |

## 七、ai-sdk 工作量评估

| 模块 | 工作内容 | 复杂度 |
|------|----------|--------|
| TTS Client | 接收数据逻辑 | 中 |
| Opus 解码 | 集成 esp_opus_dec | 低 |
| 重采样 | 集成 esp_ae_rate_cvt | 低 |
| 播放队列 | FreeRTOS 队列管理 | 中 |
| Audio HAL | 统一接口定义 | 低 |
| ES8311 驱动 | 集成 esp_codec_dev | 中 |
| ES8388 驱动 | 集成 esp_codec_dev | 中 |
| NoCodec 驱动 | I2S 直连 | 中 |
| PDM 驱动 | I2S PDM 模式 | 中 |
| 配置系统 | Kconfig 或结构体 | 低 |

---

## 八、方案优缺点

### 优点

1. **厂商接入简单** - 只需要配置引脚
2. **统一维护** - 所有驱动在 ai-sdk 内
3. **测试完善** - ai-sdk 统一测试

### 缺点

1. **ai-sdk 体积大** - 包含所有驱动
2. **新硬件支持慢** - 需要 ai-sdk 更新
3. **维护压力大** - ai-sdk 需要维护所有驱动

---

## 九、与另一方案对比

| 方面 | 本方案（内置驱动） | 另一方案（接口抽象） |
|------|------------------|-------------------|
| ai-sdk 工作量 | 大 | 小 |
| 厂商工作量 | 小 | 中 |
| 支持新硬件 | 需要 ai-sdk 更新 | 厂商自己加 |
| 灵活性 | 低 | 高 |
| 维护负担 | 集中在 ai-sdk | 分散给厂商 |
